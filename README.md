# 拾要

拾要是一款本地优先的总复习工作台。目标是导入 PPT、Word 等复习资料，由使用者直接说明“什么最重要”，或把这套标准交给第三方 AI，用它整理重点并支持后续复习。

## 当前阶段

当前已完成 Phase 3，交付以下真实能力：

- 全新的拾要产品身份、本机数据目录与独立数据库；
- 复习项目的新建、查看、编辑和删除；
- 项目内“概览、资料、分析、重点、复习、掌握情况”六步工作区；
- 多个 OpenAI 兼容或 Anthropic 第三方 AI 服务；
- API 地址规范化、模型列表获取、手动模型回退与默认服务选择；
- 文本、结构化输出、视觉和提示词缓存能力徽标；
- 明确的鉴权、权限、地址、限流和能力校验错误提示。
- PDF、DOCX、PPTX、TXT、Markdown 资料导入、稳定内容块和页面预览；
- 选定内容块或整个项目的后台 AI 分析、范围/额度提醒、取消与失败重试；
- 解析缓存、第三方提示词缓存信号和本机精确结果缓存；
- AI 候选重点的来源回看、编辑、批量确认/拒绝，以及正式重点的增删改排。

以下能力将在后续阶段接入：

- 原题生成、正式复习和掌握情况统计；
- 新身份下的 Windows 安装包、快捷方式和发布流程。

## 资料导入与降级规则

直接支持 `.pdf`、`.docx`、`.pptx`、`.txt` 和 `.md`。旧版 `.doc`、`.ppt` 也可选择，但必须在 Windows 上安装对应的 Microsoft Word 或 PowerPoint；无法调用 Office 时会明确提示另存为现代格式，不会静默跳过。

- PDF 提取文本并生成页面预览；加密或损坏文件会要求移除密码或重新导出。
- DOCX 提取段落、标题、表格和内嵌图片。
- PPTX 始终提取幻灯片文本与讲者备注；仅在本机 PowerPoint 可用时生成幻灯片预览，否则以“解析完成，但有提醒”入库。
- TXT 与 Markdown 按文本结构生成内容块。
- 单个文件上限为 100 MB。相同项目、相同文件内容和相同解析器版本会命中解析缓存，内容块 ID 保持不变。

解析提醒表示仍有可用文本，不等于失败。界面会保留提醒，便于在发起 AI 分析前决定是否继续。

## 后台分析与确认边界

“分析”页会在请求第三方 AI 前显示资料份数、页数、内容块、字符和图片估算。大范围分析必须再次勾选确认。范围、项目重要性提示词、本次补充要求、服务商配置代次和模型都会固化到任务快照。

分析由独立 worker 处理，不在网页请求中阻塞。源码开发运行时，API 与 worker 分别启动：

```powershell
cd backend
# 终端 1
.\.venv\Scripts\python.exe -m app.runner
# 终端 2
.\.venv\Scripts\python.exe -m app.jobs.worker
```

关闭或刷新网页不会终止任务；当前项目步骤和任务编号保存在浏览器会话中，刷新后会继续读取数据库里的进度。worker 异常退出后，租约到期的任务会由新 worker 接管；已成功批次不会重复执行，临时服务商错误按持久化退避重试。

AI 输出始终先进入“候选重点”，不会自动确认。候选可修改、拒绝和回看来源；只有使用者明确确认后，才进入正式复习提纲。项目删除和资料删除会先说明影响，并级联清理关联任务、候选与正式重点。

## 缓存策略与位置

源码运行默认把正式数据放在仓库的 `data/`，运行时缓存放在 `Runtime/`；打包版使用 `%LOCALAPPDATA%\ShiyaoReview\Data` 与同级 `Runtime`。可用 `SHIYAO_DATA_DIR` 和 `SHIYAO_ROOT` 覆盖。主要目录为：

- `Runtime/parse-cache`：以文件内容哈希和解析器版本命中的解析结果与预览资产；
- `Runtime/ai-cache`：以协议、服务配置代次、模型、内容、提示词、Schema、管线版本和参数共同命中的成功 AI 结果；
- SQLite：项目、资料索引、任务/批次、候选和正式重点，属于正式数据，不是缓存。

本机 AI 缓存是严格的精确匹配；修改提示词、模型、服务地址/API Key 代次、选择范围或温度都会失配并重新请求。没有语义缓存（semantic cache）或向量数据库（vector database），也不会用相似结果代替本次分析。Anthropic 可标记稳定前缀供服务商缓存；OpenAI 兼容服务只在上游明确报告时记录缓存用量。

清除缓存只应清空 `Runtime/parse-cache` 和 `Runtime/ai-cache`，不会删除原始资料、数据库、凭据、日志或删除暂存区。清除后已有正式结果仍保留，再次解析或分析时会重新计算并可能消耗第三方额度。

## 第三方 AI 设置

首次打开 `/setup`，或在“设置”中选择“新增服务”，按六步完成接入：

1. 选择 OpenAI 兼容或 Anthropic 协议；
2. 填写 API 地址、服务名称和 API Key；
3. 获取服务商公开的模型列表；
4. 选择要使用的模型；如果服务商没有模型列表接口，可手动填写模型 ID；
5. 运行文本、结构化输出和视觉能力校验；
6. 三项必需能力均通过后启用服务，并按需设为默认服务。

地址输入区会预览实际使用的模型列表与推理端点。能力徽标中的“缓存”表示服务商是否支持或报告提示词缓存；缓存不支持不会阻止服务启用。模型列表在本机缓存 15 分钟，“刷新模型”会强制重新获取。

能力校验只发送拾要内置的固定短文本、固定 JSON Schema 和一张 1×1 测试图片，不会发送项目名称、用户提示词或任何复习资料。

## 开发运行

后端需要 Python 3.12，前端需要 Node.js 与 npm。

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
cd ..\frontend
npm ci
npm run build
cd ..
.\start.ps1
```

本机服务默认打开 `http://127.0.0.1:8000`。停止服务：

```powershell
.\stop.ps1
```

## 数据与隐私边界

- 项目、服务配置和模型校验结果以 SQLite 保存在本机，不包含账户或云同步。
- 每个服务的 API Key 使用独立的 Windows 凭据项保存，不写入数据库、日志、诊断包或备份，也不会在页面回显。
- 上传的原文件、解析块、候选和正式重点都保存在本机；只有使用者明确发起分析时，所选资料内容才会发送给当时选择的第三方 AI 服务和模型。
- 任务与错误日志只记录状态、公开错误码和已脱敏信息，不记录 API Key、提示词全文、资料正文或模型原始回答。
