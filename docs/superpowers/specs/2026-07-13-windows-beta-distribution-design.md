# Windows 小范围测试版分发设计

## 状态

已由用户确认。本文记录已在对话中逐段确认的设计，不包含实现计划。

## 目标

把现有半导体课后复习助手交付给 1～5 位认识的同学或朋友试用。测试者使用 Windows 10/11 64 位电脑，能够通过标准安装包完成安装，不需要 Python、Node 或管理员权限，并使用自己的 OpenAI 兼容 API 地址、密钥和模型。

成功标准：测试者可以自行安装、首次配置、导入课件、完成复习、备份数据和覆盖升级；过程中不接触命令行，不共享开发者的密钥，也不会因升级或卸载误丢个人数据。

## 已确认的产品边界

- 首批用户：1～5 位已知且可信任的测试者。
- 系统：仅 Windows 10/11 64 位。
- 界面：继续使用默认浏览器，不增加独立桌面窗口。
- 安装：当前用户安装，不请求管理员权限。
- AI：每位用户配置自己的 OpenAI 兼容 API；Codex 作为高级可选后端。
- 更新：开发者手动发送新版安装包，用户覆盖安装。
- 签名：测试版暂不购买代码签名证书，允许出现 SmartScreen 提示。
- PPT/PPTX：本机有 Microsoft PowerPoint 时支持；否则提示转换为 PDF。
- 发布：源码同步到公开 GitHub 仓库，安装包通过公开 GitHub Release 提供下载。

## 方案选择

采用 PyInstaller `onedir` 加 Inno Setup：

1. React/Vite 先生成静态前端。
2. PyInstaller 将 Python、FastAPI、运行依赖和前端静态文件打包为目录式应用。
3. Inno Setup 把目录式应用封装为单个 `Setup.exe`，负责安装、快捷方式、覆盖升级和卸载。

不采用 PyInstaller `onefile`，因为安装器已经提供单文件交付，运行时再次解压只会增加启动、资源路径和杀毒软件兼容成本。不采用 Nuitka 作为第一版主线，因为 C 编译链和依赖适配会增加测试版维护成本。

## 安装布局

程序文件安装到：

```text
%LOCALAPPDATA%\Programs\SemiconductorReview\
```

个人持久数据保存到：

```text
%LOCALAPPDATA%\SemiconductorReview\
├── Data\       SQLite、课程、课件和页面文件
├── Backups\    自动安全备份
├── Logs\       轮转后的脱敏运行日志
└── Runtime\    端口、PID 和单实例运行元数据
```

程序目录可以被覆盖更新；持久数据目录不随程序更新而替换。开发环境继续允许显式覆盖数据路径，便于自动化测试。

安装器执行以下动作：

- 使用非管理员安装模式安装到当前用户目录；
- 创建桌面和开始菜单快捷方式；
- 注册当前版本号和卸载入口；
- 更新或卸载前通过本地控制通道安全停止正在运行的服务，等待 SQLite 释放后再替换文件；
- 覆盖升级时替换程序文件但保留个人数据；
- 安装完成后允许用户立即启动应用。

## 启动与单实例

安装后的快捷方式启动打包生成的入口程序，不再调用 PowerShell 脚本。入口程序负责：

1. 获取当前用户范围的应用互斥锁；
2. 读取 `Runtime` 中的已有实例信息；
3. 通过带应用标识和协议版本的就绪接口验证实例；
4. 实例健康时直接打开浏览器；
5. 没有健康实例时选择一个可用的本地端口，启动 FastAPI；
6. 写入运行元数据，等待数据库就绪，再打开默认浏览器。

服务只监听 `127.0.0.1`，不接受局域网或公网连接。端口不固定为 8000，从而避免测试者电脑上的端口冲突。前端使用相对 API 路径，因此跟随实际端口运行。

关闭浏览器不停止后台服务；再次启动只重新打开页面。设置页提供“退出本地服务”，确认后安全释放 SQLite 并关闭后台进程。Windows 注销或关机时也执行相同的安全退出流程。

## 资源与 PowerPoint 能力

打包程序使用统一的资源定位层区分：

- 只读程序资源：前端静态文件、默认模板和版本信息；
- 可写个人数据：数据库、上传文件、缓存、日志和备份。

PDF导入不依赖 Office。PPT/PPTX 导入启动前检测 PowerPoint COM 能力：

- 检测成功时通过 PowerPoint 导出 PDF，再进入统一页面管线；
- 检测失败时不尝试安装 Office，也不显示底层 COM 错误，只提示用户先转换为 PDF。

## 首次启动与 AI 配置

首次启动进入短配置引导：

1. 输入 OpenAI 兼容 API 地址；
2. 输入个人 API Key；
3. 选择或填写模型；
4. 测试认证、文字、视觉和结构化输出能力；
5. 测试通过后进入首页。

API Key 仅保存到当前用户的 Windows 凭据存储。数据库只保存服务地址、模型和能力配置；日志、诊断包和备份不得包含密钥。

OpenAI 兼容 API 是测试版默认入口。Codex 后端放在“高级选项”中，只有检测到本机可用凭据和能力后才能启用。两个后端仍由用户手动切换，失败时不自动转发。

发送课件前保留隐私提示：只有用户选中的页面、提取文字和课堂补充信息会发送给当前配置的 AI 服务。

## 数据、备份与迁移

SQLite仍是单机正式数据的唯一权威来源。备份导出继续包含课程、课件、题目、答案、复习历史和排期，但排除：

- API Key及其他凭据；
- 运行时 PID、端口和日志；
- 临时缓存和可重新生成的文件。

覆盖升级需要数据库迁移时：

1. 启动前检测数据版本；
2. 在 `Backups` 创建带版本号和时间的安全备份；
3. 在事务中执行迁移；
4. 迁移失败则回滚并停止启动，不继续写入数据；
5. 保留最近 5 份自动安全备份，生成第 6 份后删除最旧文件。

卸载默认只删除程序。卸载界面提供“同时删除个人数据”，但该选项默认不勾选，并在执行前再次明确警告。

## 手动更新与版本兼容

测试版使用 `0.1.0-beta`、`0.1.1-beta` 形式的版本号。每次更新由开发者发送新的安装包，用户直接覆盖安装。

覆盖安装必须满足：

- 保留 API 配置、凭据、课程、课件和复习历史；
- 不重复创建快捷方式；
- 新程序能够识别旧数据版本并执行受控迁移；
- 迁移失败时给出可操作的错误和数据目录位置；
- 旧版安装包和更新前自动备份可以用于人工恢复。

第一版不实现自动更新、后台下载或远程强制升级。

## 日志、诊断与错误处理

程序错误以用户可理解的信息显示，同时把技术细节写入轮转日志。日志必须对密钥、认证头和可能含敏感信息的请求内容做脱敏。单个日志最大 5 MB，最多保留 5 个历史文件。

设置页提供：

- 打开数据目录；
- 打开日志目录；
- 导出诊断包；
- 退出本地服务。

诊断包只包含应用版本、Windows版本、安装方式、AI能力配置和脱敏日志。默认不包含 API Key、课件、答案或数据库。

常见失败的处理：

- 端口冲突：自动选择其他本地端口；
- 数据库不可用：不打开页面，显示备份与数据目录入口；
- API认证失败：保留配置页并显示服务返回的安全摘要；
- 模型不支持视觉：禁止图片课件生成并提示更换模型；
- PowerPoint不可用：提示转换 PDF；
- 程序文件损坏：建议覆盖安装，不触碰个人数据。

## 构建和发布流程

构建只在 Windows 64 位环境中执行：

1. 运行现有后端和前端测试；
2. 构建 React 前端；
3. 运行 PyInstaller `onedir` 构建；
4. 对打包目录执行启动、导入和复习烟雾测试；
5. 用 Inno Setup 生成当前用户安装包；
6. 在干净的 Windows 10/11 64 位环境中安装验证；
7. 生成安装包 SHA-256；
8. 交付安装包、校验值和一页式使用说明。

发布产物示例：

```text
半导体复习台-0.1.0-beta-Setup.exe
半导体复习台-0.1.0-beta-SHA256.txt
安装与使用说明.pdf
```

由于测试版不签名，说明文档必须解释 SmartScreen 的“更多信息 → 仍要运行”，并强调安装包只应从开发者本人处获取。

## GitHub 仓库与 Release

目标仓库为公开仓库 `angle1592/semiconductor-review-assistant`。源码、构建脚本、安装脚本、测试和文档进入 Git；`dist`、`build`、PyInstaller 临时文件和安装包不进入 Git 历史。

首次公开推送前必须扫描当前文件和完整 Git 历史，确认不存在 API Key、认证头、Windows 凭据、真实课件或个人复习数据。测试阶段不添加开源许可证；公开可见不等于授予复制、修改或再分发许可。

每个测试版本创建带注释标签，例如 `v0.1.0-beta`，并建立对应 GitHub Release。Release 至少上传：

- `半导体复习台-0.1.0-beta-Setup.exe`；
- `半导体复习台-0.1.0-beta-SHA256.txt`；
- `安装与使用说明.pdf`。

Release 说明包含支持系统、未签名 SmartScreen 提示、PowerPoint要求、个人 API 配置、覆盖升级和数据保留说明。上传完成后从 GitHub Release 实际下载一次，校验 SHA-256 并执行安装烟雾测试。

## 测试与验收

自动化和人工验收至少覆盖：

- 没有 Python、Node 的干净 Windows 10/11 64 位电脑能够安装和启动；
- 安装和日常启动不请求管理员权限；
- 连续双击只产生一个后台服务；
- 固定端口被占用时仍能启动；
- 浏览器关闭后可以再次打开原实例；
- PDF导入、页面来源追溯和复习闭环正常；
- 有 PowerPoint时 PPT/PPTX 可导入，没有时提示准确；
- 用户自己的 OpenAI 兼容 API能够完成连接测试和生成；
- 断网时已有题目仍可复习；
- 重启、覆盖升级和数据库迁移后数据完整；
- 更新和卸载能够先安全停止正在运行的服务；
- 备份恢复结果一致，备份中不含密钥或运行时文件；
- 卸载默认保留数据，重新安装后可以继续使用；
- 安装包、程序目录、数据库、日志和诊断包均不含开发者的 API Key。
- GitHub 仓库历史和 Release 附件通过密钥与个人数据扫描；
- 从公开 Release 下载的安装包校验值一致并可以完成安装。

## 明确不做

第一版分发不包含：

- 自动更新；
- 账户和登录；
- 云同步和多人共享；
- 手机端；
- 联网授权或许可证系统；
- 代码签名证书；
- macOS、Linux、Windows ARM或旧版 Windows；
- 独立桌面窗口；
- 自动安装 Microsoft PowerPoint；
- 远程收集日志或使用数据。
- 测试阶段的开源许可证授权。

## 第一轮试用反馈

测试者只需要反馈四类信息：

1. 是否可以独立完成安装和首次配置；
2. 日常 10～15 分钟复习流程是否顺畅；
3. 哪类课件、模型或系统环境失败；
4. 覆盖升级后数据是否完整。

第一轮目标是验证“可安装、可使用、可升级、数据不丢”，而不是扩大功能范围。
