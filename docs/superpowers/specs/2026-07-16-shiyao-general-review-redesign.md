# 拾要：通用资料总复习工具重构设计

## 状态

本设计已于 2026-07-16 经用户逐节确认。它取代现有“半导体课后复习台”的产品定位，作为后续实现和验收的唯一产品设计基线。

## 目标

将现有应用重构为本地优先的通用资料总复习工具“拾要”。用户以“复习项目”组织 PDF、PPT/PPTX、DOC/DOCX、TXT 和 Markdown 资料，自行选择重要范围，或让第三方 AI 扫描整份资料提出候选重点。用户确认重点后，再按需生成提纲、记忆卡和练习题，并记录掌握情况。

核心闭环为：

```text
导入资料 → 确定分析范围 → 提取并确认重点 → 按需复习 → 记录掌握度
```

## 产品名称与定位

- 产品名：`拾要`
- 副标题：`从资料中拾取真正重要的内容`
- 适用范围：通用课程、考试和专业学习，不限定半导体领域。
- 核心原则：AI 只能提出候选内容；用户确认后的重点清单才是复习范围的权威来源。

## 第一版边界

第一版包含：

- 复习项目管理；
- 知识材料与题目资料混合导入；
- 人工选页/章节与 AI 全文扫描两种分析入口；
- 候选重点确认和三级重要度；
- 原题保留及 AI 新题、变式题、错因题；
- 提纲、记忆卡、原题练习和 AI 题练习；
- 掌握度记录；
- OpenAI 兼容与 Anthropic 两种第三方 API 协议；
- 精确结果缓存、提供商提示缓存和可恢复 AI 任务；
- 本地备份、日志、诊断和 Windows 安装包。

第一版不包含：

- Codex SDK、本机 Codex 登录或 Codex 凭据；
- 考试日期、每日任务或自动复习排期；
- 账户、云同步、多人协作或移动端写入；
- 向量数据库、语义缓存、聊天式知识库或资料问答；
- 自动判断用户必须学习什么并绕过人工确认；
- Redis、外部任务队列或外部数据库。

## 信息架构

### 主导航

- `项目`：创建和管理复习项目。
- `开始复习`：从任意项目选择重点和复习方式。
- `掌握情况`：按项目、重点等级和掌握状态筛选。
- `设置`：AI 服务、数据、备份、日志和应用信息。

### 复习项目页签

1. `概览`：资料数量、已确认重点、原题数量、掌握情况和下一步建议。
2. `资料`：上传、分类、解析状态、缩略图、重新解析和删除。
3. `重点`：候选重点与正式重点分区，支持来源和重要度筛选。
4. `复习`：选择提纲、记忆卡、原题或 AI 生成题，并设置范围、题型和数量。
5. `掌握情况`：展示练习次数、正确情况及“已掌握/模糊/不会”。

项目内不显示日历、倒计时或自动排期。

## 核心数据模型

### ReviewProject

表示一个复习项目，包含名称、说明、项目级重要性提示词、创建时间和更新时间。

### SourceDocument

表示用户上传的一份资料，包含：

- 类型：`knowledge` 或 `question_bank`；
- 原始文件名、格式、内容哈希和存储位置；
- 解析状态、解析器版本和错误摘要；
- 是否具备完整视觉版式；
- 创建时间和更新时间。

### SourceBlock

统一表示 PDF 页面、PPT 幻灯片、Word 页面/段落、TXT/Markdown 标题或段落，包含：

- 在资料中的稳定顺序和来源位置；
- 规范化文本；
- 页面图片或内嵌图片引用；
- 内容哈希；
- 结构信息，例如标题、表格和页码；
- 为未来全文检索和向量索引保留的稳定 ID。

### AnalysisRun 与 AnalysisBatch

`AnalysisRun` 记录一次重点分析的模式、实际提示词、提供商、模型、输出格式版本和选择范围。`AnalysisBatch` 记录分批任务的输入块、状态、重试次数、结果和脱敏错误。

分析模式为：

- `manual_scope`：用户先选页或章节；
- `ai_full_scan`：AI 扫描整份资料并提出候选重要页、理由和候选重点。

### KeyPoint

重点包含标题、解释、原文依据、来源块和三级重要度：

- `core`：核心必会；
- `important`：重点理解；
- `supplementary`：补充了解。

重点状态分为 `candidate` 和 `confirmed`。只有 `confirmed` 重点可以用于正式复习内容生成。

### SourceQuestion

保存题目资料中的原题，包含题干、选项、原答案、原解析、题型和来源位置。AI 无法可靠识别答案时必须标记为“不确定”，不得把推测内容伪装成原答案。

### GeneratedArtifact

保存可版本化的提纲、记忆卡、AI 新题、变式题和错因题，记录对应重点、生成模型、提示词版本和时间。重新生成时，用户选择保留旧版本或替换当前版本。

### StudyAttempt 与 MasteryRecord

`StudyAttempt` 保存一次练习的题目、回答和评价。`MasteryRecord` 汇总练习次数、正确情况及“已掌握/模糊/不会”。掌握记录只用于筛选和建议，不生成自动排期。

### AIProviderProfile 与 ModelProfile

允许保存多套 OpenAI 兼容或 Anthropic 服务配置。一个提供商配置包含显示名称、协议、规范化 API 地址、密钥引用、启用状态和验证状态。一个模型配置包含模型 ID、显示名、能力校验结果和校验时间。

API Key 只保存于 Windows 凭据库；数据库只保存不可用于认证的凭据引用和末尾四位显示信息。

## 资料导入与解析

### 格式处理

- PDF：直接提取每页文字并渲染页面图片。
- PPT/PPTX：有 PowerPoint 时先转 PDF，进入统一页面管线；无 PowerPoint 时，PPTX 降级提取文字和内嵌图片，PPT 提示先转换。
- DOC/DOCX：有 Word 时先转 PDF；无 Word 时，DOCX 提取段落、表格和内嵌图片，但明确提示无法保证原始分页，DOC 提示先转换。
- TXT/Markdown：按标题和段落生成内容块。

降级解析必须显示“版式/视觉信息可能不完整”，不得把降级结果标记为完整视觉解析。

### 导入步骤

```text
上传文件 → 确认资料类型 → 本地解析 → 选择分析方式 → AI 分析 → 确认重点
```

上传后由用户确认“知识材料”或“题目资料”。AI 可以建议资料类型，但不能替代用户确认。

### 分析入口

“我来选范围”通过缩略图或章节列表勾选内容，AI 只接收所选范围。

“AI 扫描整份资料”在发送前展示页数、提供商、模型、将发送的内容和隐私提示。AI 返回候选重要页、选择理由和候选重点；用户仍须在重点确认页增删、改写和调整重要度。

项目级重要性提示词是默认值，每次分析前可以临时修改。没有自定义提示词时，使用内置标准：核心概念、原理步骤、易混点、公式参数和高频题型。

## 复习方式

重点确认后不自动生成所有内容。用户进入“复习”页时选择：

- 查看提纲；
- 使用记忆卡；
- 练习原题；
- 生成并练习 AI 新题。

AI 新题可选择普通新题、变式题或错因题，并设置题型、数量和重点范围。原题与 AI 题必须有明显标识，所有题目保留来源重点和来源资料。

## 第三方 API 接入

### 配置流程

```text
选择协议 → 填写地址与密钥 → 获取模型 → 选择模型 → 能力校验 → 启用
```

设置页以“AI 服务”卡片管理多套配置。卡片展示协议、地址、密钥状态、模型、验证状态和启用状态。同一时间选择一套默认服务和模型；开始分析前允许临时切换。

配置可以保存但不启用。只有选定模型通过当前任务所需能力校验后，才能用于正式分析。

### 地址规范化

- 输入框下实时显示最终模型列表和推理请求地址。
- OpenAI 兼容地址避免重复拼接 `/v1`；Anthropic 地址避免重复拼接 `/v1/models` 和 `/v1/messages`。
- 非标准提供商若不支持模型列表，可以手动填写模型 ID，但推理接口仍须兼容所选协议。
- 切换协议时解释 OpenAI Bearer 和 Anthropic `x-api-key` 的区别。

### 模型获取

- OpenAI 兼容协议调用 `GET /v1/models`。
- Anthropic 协议调用 `GET /v1/models`。
- 获取到的模型进入候选列表，由用户选择添加，不自动启用全部模型。
- `401/403`、`404/405`、超时和响应格式错误分别处理；模型列表端点不受支持时允许手动输入。

### 能力校验

模型选择后依次进行：

1. 极短文本生成测试；
2. 规定 JSON 结构的结构化输出测试；
3. 使用程序自带无隐私图片的视觉测试。

模型显示“文本、结构化输出、视觉”能力徽章。能力以实际测试为准，不只根据模型名称推断。视觉资料只能使用通过视觉测试的模型。

连接测试与能力测试不得发送用户资料。API 地址、密钥或模型变化后，旧验证结果立即失效。

### 错误提示

- `401/403`：密钥无效、权限不足或无权访问模型。
- `404/405`：地址、协议或模型列表端点不匹配。
- `429`：额度不足或请求频率过高。
- 模型不存在、超时、TLS、代理、DNS 和响应格式错误分别显示。

错误区域提供“重试、修改配置、手动填写模型、缩小范围、查看技术详情”等操作。技术详情必须脱敏，可复制但不得包含完整密钥或资料正文。

## AI 任务与恢复

长时间 AI 分析不在普通 HTTP 请求中阻塞。应用启动时管理一个独立本地工作进程：

1. API 将任务和批次写入 SQLite；
2. 工作进程逐批调用第三方 AI；
3. 每批成功后立即保存结果和 token 用量；
4. 前端通过 React Query 轮询任务进度；
5. 页面关闭、浏览器刷新或应用重启后继续未完成批次；
6. 已成功批次不重复执行；
7. 取消任务只停止未开始批次并保留已完成结果。

任务状态为 `pending`、`running`、`partial`、`failed`、`cancelled` 或 `succeeded`。每个任务和批次使用稳定 ID，重试必须幂等。

## 缓存设计

缓存只覆盖能够明确节省时间或 API 费用的内容，不引入 Redis。

### 前端数据缓存

React Query 缓存本地 API 查询结果，并在相关写操作成功后精确失效。

### 文件解析缓存

使用“文件 SHA-256 + 解析器版本”作为键，复用规范化文本、页面图片和结构信息。解析器版本变化后自动重新解析。

### 模型信息缓存

- 模型列表缓存 15 分钟，并提供“立即刷新”。
- 能力校验长期保存，直到 API 地址、凭据代次或模型发生变化。
- 失败结果不进入长期缓存。

### 模型端提示缓存

- 提示结构保持稳定顺序：系统规则、输出格式、稳定资料上下文、变量任务指令。
- Anthropic 在提供商支持时使用 `cache_control`；第三方代理拒绝该字段时显示“不支持提示缓存”，允许关闭后继续使用。
- OpenAI 兼容接口利用提供商的精确前缀缓存；接口返回 cached token 时记录并展示。
- 提供商不报告缓存用量时显示“服务商未报告”，不估算或伪造节省金额。

### 本地 AI 精确结果缓存

缓存键包含：

```text
协议 + 服务配置代次 + 模型 + 内容哈希 + 提示词 + 输出格式版本 + 生成参数
```

只有所有字段完全一致才命中。命中时提示用户选择“复用已有结果”或“强制重新生成”。失败、取消和无法验证的输出不缓存。

### 不做语义缓存

第一版不根据相似度复用不同资料或不同问题的 AI 结果。语义缓存随未来向量检索能力单独设计。

### 正式数据与缓存的区别

用户确认的重点、保存的提纲、记忆卡、题目和掌握记录是正式数据，不受缓存 TTL 影响。缓存删除后只能导致重新解析或重新调用，不能删除正式成果。

## 技术架构

保留现有技术基础：

- React 19 + TypeScript + React Query；
- FastAPI + SQLModel + SQLite；
- 本机 REST API；
- Windows 当前用户安装；
- 仅监听 `127.0.0.1`。

不增加账户和认证。前后端继续使用统一错误格式和请求 ID。

后端按领域拆分：

- `projects`：复习项目；
- `sources`：资料和统一内容块；
- `analysis`：范围、任务、批次和候选重点；
- `key_points`：重点确认、分级和来源；
- `questions`：原题与 AI 题；
- `study`：复习成果、练习和掌握记录；
- `providers`：OpenAI 兼容、Anthropic、模型获取和能力校验；
- `shared`：数据库、错误、日志、凭据库和文件安全。

AI 提供商使用统一接口：获取模型、校验能力、分析内容块和生成复习内容。未来知识库能力通过新增索引和检索接口扩展，不改变资料、内容块和重点的稳定 ID。

## 操作提示

所有长流程使用步骤条。每一步只显示当前主操作，并用主按钮指向下一步。

开始 AI 操作前展示范围、页数、提供商、模型和发送内容。运行中展示当前批次、完成进度和取消按钮。按钮被禁用时必须在旁边说明原因。

删除资料或重点前展示会连带删除的复习成果和掌握记录数量。离开未保存配置、覆盖已验证 API 配置或删除正在使用的服务时明确确认。

## 数据重置与 Codex 删除

实现新版本时执行一次明确的数据重置：

1. 停止工作区当前服务并释放 SQLite 和文件句柄；
2. 清空工作区 `data/`、`Backups/`、`Logs/`、`Runtime/` 的内容；
3. 保留上述目录结构；
4. 不触碰 `%LOCALAPPDATA%\SemiconductorReview` 中已安装版本的数据；
5. 不创建旧数据库迁移；
6. 创建带新产品标识和新架构版本的空数据库。

完整删除：

- Codex SDK 依赖和锁文件项；
- Codex 提供商、适配器和错误类型；
- 本机凭据和登录状态检测；
- Codex 设置入口和模型选项；
- Codex 单元、集成和端到端测试；
- 构建脚本中的 Codex 安装步骤；
- README、用户指南、发布说明和诊断信息中的 Codex 描述。

重置和删除发生在实现阶段，不在设计阶段执行。

## 数据安全、备份和诊断

备份包含原始资料、确认重点、原题、复习成果、掌握记录和非敏感配置。

备份默认排除：

- API Key 和认证字段；
- 页面图片等可再生解析缓存；
- 模型列表和 AI 精确结果缓存；
- 运行时 PID、端口和任务锁；
- 日志和临时文件。

日志记录请求 ID、服务、模型、耗时、状态和 token 统计，不记录资料正文、题目正文或密钥。诊断包同样排除原始资料、数据库、答案和凭据。

删除复习项目时，其资料、重点、题目、复习成果和掌握记录一起删除；其他项目不受影响。多文件删除使用数据库事务和可恢复文件回收流程。

## 失败处理

- AI 批次失败不回滚已经完成的批次和人工编辑。
- AI 返回无效 JSON、引用未发送来源或缺少必要字段时，该批结果不进入候选重点。
- 应用崩溃或断电后，只恢复数据库中可验证的任务状态。
- 临时文件和半成品在启动恢复流程中核对归属后清理。
- 数据库迁移或新版本初始化失败时停止写入并显示数据目录和日志入口。

## 未来知识库扩展

第一版不实现方案 3 的向量知识库，但保留以下扩展点：

- `SourceBlock` 具有稳定 ID、规范化文本、内容哈希和来源位置；
- AI 提供商接口可以新增 embedding 能力而不修改现有分析接口；
- 可以按项目建立独立索引；
- 检索结果仍引用资料块和正式重点；
- 未来资料问答与当前复习成果分开存储；
- 语义缓存只有在向量索引、相似度阈值和可解释命中记录设计完成后才启用。

## 测试策略

### 解析测试

覆盖 PDF、PPTX、DOCX、TXT、Markdown、文字、表格、图片、空白页、损坏文件、无 Office 降级和旧格式提示。

### AI 协议测试

分别模拟 OpenAI 兼容和 Anthropic 的模型列表、文本、结构化输出、视觉、提示缓存、超时、限流、认证失败和异常响应。

### 缓存测试

验证文件哈希、提示词、模型、服务配置代次、输出格式版本和参数变化会正确命中或失效。失败结果不得缓存，成功批次不得重复执行。

### 领域与 API 测试

覆盖项目、资料、候选重点、正式重点、原题、AI 题、复习方式、掌握记录、备份和级联删除。

### 前端与端到端测试

覆盖首次配置、模型获取与校验、明显操作提示、上传、人工选页、AI 全文扫描、重点确认、四种复习入口、错误恢复和删除确认。

### Windows 验收

- 普通用户权限下安装、启动、升级和卸载，不请求管理员权限；
- 有 Office 和无 Office两种环境符合设计；
- 刷新页面和重启应用后 AI 任务可继续；
- OpenAI 兼容与 Anthropic 服务各完成真实小范围烟雾测试；
- API Key 不出现在数据库、备份、日志、诊断包或安装产物中；
- 重置后只生成新架构数据库；
- 源码、依赖、构建产物和界面中不再包含 Codex 接入；
- 安装包完成完整主流程。

完整主流程为：

```text
创建项目 → 上传资料 → 选择范围 → 确认重点 → 生成复习内容 → 完成练习 → 查看掌握情况 → 导出备份
```

## 验收标准

没有技术背景的用户仅依靠界面提示，可以完成完整主流程。任何失败都能知道“哪里错、为什么、下一步怎么做”。

AI 只能处理用户明确选择或确认发送的内容。正式重点必须有可追溯来源，并经过用户确认。原题、AI 题和推测答案必须明确区分。

重复执行完全相同的解析或 AI 分析时，应用能说明缓存命中情况，并允许用户选择复用或重新生成。
